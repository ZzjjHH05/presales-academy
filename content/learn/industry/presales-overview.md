## 📌 一句话结论

售前工程师 = **销售的技术搭档 + 方案的作者 + 讲标的主角**：在"卖出去"之前，负责把客户需求翻译成解决方案并让它被认可。

## 🧠 知识要点

### 售前在一条销售流程里的位置

一条典型的 ToB 销售流程大致是：

1. 线索/商机发现（销售主导）
2. 需求了解与立项（售前开始介入：陪访、需求调研）
3. 方案设计与呈现（售前主笔：方案书、交流汇报、POC 演示）
4. 招投标与讲标（售前主笔标书 + 讲标答疑）
5. 商务谈判（销售/商务主导，售前支持技术条款）
6. 中标/合同签订
7. 交付与验收（售后/交付团队主导，售前移交）

> 一句话：**售前的产出物是"让客户和评委信服的东西"**——方案书、汇报材料、标书、Demo、答疑。

### 售前与相邻岗位的分工

| 岗位 | 关注点 | 典型产出 |
|---|---|---|
| 销售 | 关系、价格、商务、回款 | 合同、报价、客户关系 |
| 售前 | 需求、方案、演示、标书 | 方案书、PPT、标书、POC |
| 售后/交付 | 上线、实施、运维 | 实施计划、验收报告 |
| 研发/产品 | 产品功能、路线图 | 产品版本、技术文档 |

### 售前常见三种细分

- **售前顾问/解决方案工程师**：偏方案与客户场景，是主力方向；
- **技术售前/方案架构师**：偏技术深度，负责技术架构与 POC；
- **行业售前**：深耕某个行业（政务、金融、制造等），懂业务 > 懂代码。

## 💼 面试怎么问

- "售前和销售有什么区别？" → 答职责边界：销售管"卖得出去"，售前管"卖得专业"；
- "你理解售前最重要的能力是什么？" → 需求理解 + 方案表达 + 应变（不是写代码）；
- "为什么想转售前 / 投售前？" → 结合自己"技术背景 + 喜欢跟人打交道/讲东西"的定位说。
