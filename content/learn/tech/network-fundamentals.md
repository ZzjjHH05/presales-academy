## 📌 一句话结论

售前不需要会抓包，但要能在客户问"你们方案走什么协议、端口、是否 HTTPS"时**不卡壳**：核心是记住**四层模型 + HTTP/HTTPS 区别 + DNS 大致流程 + 几个高频端口**。

## 🧠 知识要点

### TCP/IP 四层模型（售前够用版）

| 层 | 干什么 | 售前常听到的东西 |
|---|---|---|
| 应用层 | 应用之间怎么说话 | HTTP/HTTPS、DNS、SSH、SMTP |
| 传输层 | 端到端可靠/不可靠 | TCP（可靠）、UDP（快但可能丢） |
| 网络层 | 跨网寻址转发 | IP、路由 |
| 链路层 | 同网段传输 | 以太网、MAC |

> 讲法："分层是为了各管各的，应用层只关心业务，不用管底层怎么传——所以做方案时我们盯着应用层和传输层，底下交给网络/机房。"

### HTTP vs HTTPS（高频考点）

- **HTTP**：明文传输，默认端口 **80**；中间人可窃听篡改。
- **HTTPS**：HTTP + TLS 加密，默认端口 **443**；需要**证书**，保证机密性、完整性、身份可信。
- 为什么客户在意：政企/金融项目几乎都强制 HTTPS，**证书要在方案里列清楚**（自签 / CA / 国密证书是加分项）。

### DNS（域名解析，一句话流程）

浏览器输入域名 → 查 DNS → 拿到 IP → 建立连接。售前只要会讲："DNS 把好记的名字翻译成机器找得到的 IP，解析慢或被劫持会直接影响访问，方案里要考虑内网 DNS 和冗余。"

### 常见端口（背得起来就够）

| 端口 | 服务 |
|---|---|
| 22 | SSH（远程登录） |
| 53 | DNS |
| 80 | HTTP |
| 443 | HTTPS |
| 3306 | MySQL |
| 6379 | Redis |

### 售前常被带的两个概念

- **公网 IP / 内网 IP**：公网可被外网访问，内网只在局域网内；上云方案常讲"公网入口 + 内网服务"。
- **负载均衡**：前面一个入口，把流量分发到后面多台机器，保可用、可扩展——几乎每个方案都会画到。

## 💼 面试怎么问

- "HTTP 和 HTTPS 有什么区别？" → 明文 vs 加密、80 vs 443、需要证书；
- "为什么 HTTPS 更安全？" → TLS 加密 + 证书验证身份，防窃听篡改；
- "DNS 是干什么的？" → 域名翻译成 IP，解析慢会影响访问；
- "一个 URL 在浏览器里发生了什么？" → DNS 解析 → TCP 连接 → TLS 握手（HTTPS）→ HTTP 请求 → 响应渲染。
