## 📌 一句话结论

售前对技术的要求是**广度优先、深度按需**：能看懂客户 IT 环境的一张图，并把自家方案放进这张图里讲。

## 🧠 知识要点

### 一张"现代 IT 基础设施地图"

从下往上大致是：

1. **物理层**：机房 / 数据中心、服务器、网络设备、存储；
2. **虚拟化与云层**：虚拟化（VMware/KVM）、私有云/公有云/混合云、容器（K8s）；
3. **数据层**：数据库（关系型/NoSQL）、数据仓库、大数据、对象存储；
4. **中间件与应用层**：消息队列、缓存、API 网关、微服务；
5. **安全与合规**：等保、网络安全、数据安全、零信任；
6. **管理与运维**：监控、日志、自动化、容灾备份。

> 售前只需要能在这张图上**指出位置、讲清关系**，具体参数问架构师和研发。

### 三大高频话题速记

- **网络**：组网拓扑（核心-汇聚-接入）、专线/VPN、负载均衡、带宽与延迟的关系；
- **云**：IaaS/PaaS/SaaS 分层、公有/私有/混合云、上云迁移、弹性扩缩容；
- **数据**：数据源、数据中台、数据分析链路、数据安全（分级分类）。

### "聊得专业"的三个技巧

1. 多问少说：用提问把客户环境问清楚（"你们现在存储跑在裸机还是虚拟化？"）；
2. 画图对齐：讲方案先画一张架构图，和客户对齐"我们现在在哪、要去哪"；
3. 不懂就记：遇到不懂的技术名词记下来，会后查，别当场硬编。

## 💼 面试怎么问

- "你不写代码，怎么做售前？" → 答：售前证明价值靠的是"把技术需求翻译成方案与价值"，广度 + 沟通 > 编码；
- "说说你了解的网络/云知识" → 用上面的地图分层讲，展示结构感；
- 常见考察：对云架构、数据库、安全合规的基本概念是否有常识。
