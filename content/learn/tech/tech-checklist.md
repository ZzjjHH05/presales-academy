## 📌 一句话结论

售前的技术要求是"**广而不深**"：每个领域懂到"能听懂、能提问、能翻译、能讲取舍"即可。

## 🧠 知识要点

### 售前技术清单（自测打分：0 不懂 / 1 听过 / 2 能聊 / 3 能讲方案）

| 领域 | 售前要会的"一句话" | 自测 |
|---|---|---|
| 网络 | 组网拓扑、专线/VPN、负载均衡、带宽延迟关系 | ☐ |
| 云 | IaaS/PaaS/SaaS、公有/私有/混合、上云迁移 | ☐ |
| 虚拟化/容器 | 虚拟机 vs 容器、K8s 是干嘛的 | ☐ |
| 数据库 | 关系型 vs NoSQL、读写分离、主备/集群 | ☐ |
| 安全 | 等保、防火墙/WAF、数据安全、零信任概念 | ☐ |
| 中间件 | 消息队列、缓存、API 网关的用途 | ☐ |
| 大数据 | 数据中台、数仓/数据湖、BI 分析链路 | ☐ |
| 信创/国产化 | 信创目录、国产 CPU/OS/数据库（政企必备） | ☐ |
| 存储与备份 | 集中存储、容灾备份、两地三中心 | ☐ |
| 交付运维 | 实施周期、验收标准、SLA 概念 | ☐ |

### 怎么补（按优先级）

1. **先补高频**：云、网络、数据库、安全（面试和方案出现率最高）；
2. **用认证体系打底**：云厂商架构师认证公开资料（AWS/阿里云/华为）最系统；
3. **对着客户场景学**：每个技术点配一个"客户为什么需要它"的场景，比背定义有用。

### 三个"翻译"能力

- 把技术翻译成价值（"弹性扩容" → "业务高峰不卡顿、不用多买服务器"）；
- 把客户的话翻译成技术（"我们系统总卡" → 追问瓶颈：数据库？带宽？架构？）；
- 把取舍翻译清楚（自建 vs 上云、开源 vs 商业，各有代价）。

## 💼 面试怎么问

- 常见考察：让你解释 IaaS/PaaS/SaaS、容器与虚拟机、上云顾虑——用"一句话 + 场景"回答；
- 不会的题：承认 + 展示思路（"我了解不深，我的理解是……"），别硬编。
