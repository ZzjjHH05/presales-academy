## 📌 一句话结论

好的方案不是写出来的，是**问出来的**。售前五步法：**收集 → 澄清 → 分析 → 设计 → 验证**。

## 🧠 知识要点

### 五步法详解

1. **收集**：听客户讲现状（业务、系统、痛点、约束）；工具：访谈、问卷、现场参观；
2. **澄清**：把模糊需求问成具体问题——"要快"是多快？"要安全"是防谁？
3. **分析**：区分"显性需求/隐性需求/伪需求"；评估可行性、优先级；
4. **设计**：先给方案骨架（目标 → 现状差距 → 解决路径 → 架构），再填充细节；
5. **验证**：POC/演示/原型确认，收集反馈并迭代，最后形成方案书。

### 提问技巧（SPIN 思想的简化版）

- **现状**（Situation）：你们现在怎么做的？
- **问题**（Problem）：哪里最痛？
- **暗示**（Implication）：这个痛点继续下去会怎样？
- **价值**（Need-payoff）：如果解决了，能带来什么？

### 需求收集的常见坑

- 只听"直接对接人"的需求，漏掉最终用户与决策者；
- 把"客户想要的功能"直接当"需求"，没追问背后的目标；
- 需求一变就推倒重写，没做"变更记录与影响评估"。

### 方案书的最小骨架

1. 项目背景与目标
2. 现状与问题分析
3. 总体方案与架构
4. 分模块设计
5. 实施计划与里程碑
6. 风险与应对
7. 报价与商务说明（如需）

## 💼 面试怎么问

- "客户提了个模糊需求，你怎么做？" → 用澄清问题 + 五步法回答，展示流程感；
- "遇到客户和决策者需求冲突怎么办？" → 各角色诉求不同，方案要分层满足并管理预期。
